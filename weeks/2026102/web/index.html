Terminal orientation

This may be your first time using the terminal. Thankfully the terminal is less intimidating then it first may appear. There is no need to be intimidated by the terminal, it is normally quite hard to accidentally cause issues using the terminal especially when not running as root. Additionally, as this environment is containerised the environment is isolated and should the worst happen then you can always reset the container from the original image. This guide is aimed to give a basic understanding of several terminal features, commands and methods, it should give you the basis on which you can further research and understand the terminal.

I would encourage you to try a few basic commands now. try some of the following:

  • ls - Lists the content of the working directory
  • pwd - Displays the current working directory
  • whoami - Displays the name of user which executed the command

Command Structure

The basic structure of a command is command [options] [arguments]

A command is typically an executable or a script which is stored in a directory linked to by the PATH variable, this is not particularly relevant yet but it is good to note that commands are nothing special they are just executables or scripts, you can make your own or install more you can even change the commands that typically come bundled with most Linux distros.
For instance the ls command is just a binary executable stored in /usr/bin/ls
Use the ls command to print the contents of the current directory

Options are a way type of argument which changes the way a command works, typically given to the command in the form of"flags" or "switches". Typical notation for flags is to use a single dash '-' for one letter flags e.g. 'ls -a' or a double dash for example 'ls --all'

Arguments are the data passed to a command, this may be in the form of standard input, text passed through the command or through a file. Different commands handle standard input differently and documentation should be referred to to determine specifics.
The terminal parser is responsible for splitting a command into separate arguments. Note that whitespace will usually be treat as separate arguments, if I wanted to create a file called "my file.txt" the command touch my file.txt will create files called "my" and "file.txt" as they are treat as separate inputs. There are several ways to avoid this. You can escape the space character by putting a backslash '\' in front of the space will resolve this for instance touch my\ file.txt or quotes can be used, both single and double quotes have slightly different behavior but single quotes will always treat input literally for our example you could use touch 'myfile.txt'.

using the example of ls -l ~/example-directory what is the command, what is option and what is an argument.

Documentation and Help

If you are ever unsure about a command most Linux distros come with the "info" and "man" utilities which can be used to lookup information directly in the command line. Alternatively many commands allow the use of the "--help" flag which can be used to see information about a command: "ls --help", "man ls" and "info ls" all work and give slightly different information try using them.

Other important terminology

Some other terminology is explained below:

  • Working directory - this is the directory that you are currently in. Any commands you execute from here will assume unless otherwise specified that any files to read from or write to will be in this directory.
  • Path - not to be mistaken with the PATH environment variable, a path is a reference to a file or directory. A path can start from the root directory '/' as in '/etc/passwd', we would call this an absolute path, based on the current working directory eg 'example-directory/Sarabanda.md'
  • Exit Code - An exit code is a numeric output that is returned to the shell when a command finished executing, conventionally 0 means success or command exited normally and and non-zero response is a different error. These are not typically shown on the terminal but can be a great troubleshooting tool if added to the prompt
  • Shell - A shell is the software that allows the user to interact with the operating system, we are using bash alternatives such as zsh or nushell are also popular
  • Prompt - The prompt is the string that is shown at the start of the command line to show that the terminal is ready for user input. Often it will just be a '>' symbol or it may feature other information such as the exit code of the previous command, current user or working directory

Filesystem Navigation

Now we have the basics of what the command line is out the way we must learn to use it.

Changing directory

To change directory we use the 'cd' command this can be used with an absolute path such as cd /home/ysj/example-directory or a relative path for instance cd ./example-directory note the use of the '.' in the previous command. This is not necessary but is used by convention as it refers to the current directory.

Relative paths become more powerful when you use the path '..'. This refers to the directory above this one. If you were in the directory "/home/ysj/example-directory" and you wanted to return to "/home/ysj" you may use the command "cd .." to return.

The symbol '~' may be used in certain paths. This is used at the beginning of a path to make it relative to your home folder which is equivalent to a user-area. Wherever you are in your filesystem you can use the command cd ~ to return to your home directory, or you can use cd ~/Documents to return to the documents directory.

Listing the directory

The ls command is used to list the current directory, including all files and subdirectories. Note that files beginning with '.' are considered hidden files on linux as such ls does not list them by default, if you want to list all files and directories including hidden files then the '-a' flag can be used like so ls -a.

Print Working Directory

To determine the absolute path of your current working directory the pwd command can be used. This can be helpful in an interactive shell but is often more useful when scripting as most of the time the shell prompt will include the current working directory.

Reading and writing to files

Reading and writing to files allows you to write code in the terminal, edit configuration files and store and retrieve information. There are several approaches to doing this which will be detailed below.

Cat, tail and head

The cat command is the most basic way in which you can print a file to the terminal, short for concatenate the cat command will read a file and output this to the terminal for instance cat ~/example-directory/Birinus.md will output the contents of the file Birinus.md as the name suggests, giving cat multiple files will result in the files being output one after another, concatenating them.

The tail and head commands allow you to get a specific number of lines from the beginning or end of a file respectively. This can be extremely useful when dealing with structured data for instance a log file in CSV format will contain the headings for each value on the first line and typically new entries are added to the bottom of the file. An example of the use of this would be echo "$(head -n 1 ~/example-directory/openvpn.csv)\n$(tail -n 1 ~/example-directory/openvpn.csv)" which would output the header row and most recent entry in the log file.

The less and more commands allow you to read a file interactively and both have very similar behavior, the main difference is that less is more modern and has some additional features, for instance in some environments more is unable to go back up a file if you have scrolled past the point which you wanted to read.

We can interactively read and write to files using a terminal text editor such as Vim or Nano. Vim is a modal editor meaning it has several different modes, it is optimised for use on a keyboard only terminal and can be very efficient when you are used to it. However, nano is much simpler, to open nano on a file you use the command nano [filename] you can then use the arrow keys to navigate the file and backspace or type as you would expect. Try editing one of the sample files in the docker environment.

Related is the word count command. The command counts the words in a file or in what is inputted to it. Additionally, the -l flag can be used to count the number of lines in the input rather than the number of words.

Redirection operators

It is possible to redirect the output from one command into another in several ways.

The pipe '|' is the simplest way to do this. This redirects the output of one command to the input of another. You may use this to get more complex behaviors for instance if you were to want to count the number of files in a directory you could use ls | wc -l

The '>' operator allows you to redirect the output of a command to a file, but this will overwrite the file. Alternatively, the operator '>>' can be used to append the output of a command to a file. Both of these operators will create the file if it does not already exist. These can be very useful. For instance if you want to change your hostname you can use the command echo "my-hostname" > /etc/hostname or if you had a server executable which you wanted to add the output to a log file you may use ./server >> serverlog.log.

Some commands don't allow you to use a file as the input. In such cases the '<' operator can be used, this allows you to input a file to the input of the command.

Shell Scripts

Shell scripts are a feature of a shell which it allows you to write a script which can be run on demand. For instance when you open a bash shell it will always look for the file ~/.bashrc if it finds this file then it will run it. This allows you to customise the shell prompt, set aliases or enforce certain behaviors which you want to occur each time you open the terminal. Shell scripting is not just used for this, you can create installers, utilities or small programs with it. This can be very helpful as all Linux servers or computers should be able to write shell scripts.

To run most executable files including shell scripts in the terminal you can use ./myscript.sh or alternatively source myscript.sh
